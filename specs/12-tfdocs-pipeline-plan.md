# Feature 12 — Add terraform-docs to the CI/CD Pipeline

## Goal

Automatically generate and keep up-to-date a `README.md` in every Terraform module under `modules/` by running `terraform-docs` in CI (on PR) and as a pre-commit hook locally.

---

## Background

The repo contains five reusable modules, each with `variables.tf` and `outputs.tf` but no `README.md`:

- `modules/create-ec2`
- `modules/create-key-pair`
- `modules/create-tgw`
- `modules/create-tgw-vpc-attachment`
- `modules/create-vpc`
- `modules/security`

`terraform-docs` reads those files and renders a Markdown table of inputs, outputs, providers, and requirements. It can inject content into an existing `README.md` between sentinel comments, or create one from scratch.

The `envs/` directories are flat root modules, not reusable — they don't need generated READMEs.

---

## Solution Overview

Two integration points:

1. **Pre-commit hook** (local) — `terraform-docs` runs on every commit via `prek`, keeping `modules/*/README.md` in sync automatically.
2. **CI job** (GitHub Actions) — a `terraform-docs` job runs on PRs, verifies the generated output matches what is committed, and fails if it doesn't (enforce that docs are always current).

---

## Implementation Plan

### Step 1 — Add the pre-commit hook to `tools/prek.yaml`

The `antonbabenko/pre-commit-terraform` repo (already used for `tflint`) provides the `terraform_docs` hook id. Add it under the same `repo` block.

```yaml
repos:
  - repo: https://github.com/antonbabenko/pre-commit-terraform
    rev: v1.105.0
    hooks:
      - id: terraform_tflint
      - id: terraform_docs
        args:
          - --hook-config=--path-to-file=README.md
          - --hook-config=--add-apache-2-license-copyright-header=false
          - --hook-config=--create-file-if-not-exist=true
```

`--create-file-if-not-exist=true` ensures the first run generates the file if it does not already exist. Subsequent runs update the injected block between the sentinel comments terraform-docs inserts.

After editing `tools/prek.yaml`, run:

```bash
prek -c tools/prek.yaml install-hooks
```

### Step 2 — Bootstrap `README.md` files in all modules

Run the hook once against all files to seed the initial READMEs:

```bash
prek -c tools/prek.yaml run --all-files terraform_docs
```

Commit all generated `modules/*/README.md` files. These become the source of truth that CI will compare against.

### Step 3 — Add a CI job to `pipeline.yml`

Add a new job `terraform-docs` that runs on `pull_request`. It checks out the PR branch, runs `terraform-docs` in check mode for every module, and fails if any file would change.

```yaml
terraform-docs:
  name: terraform-docs
  runs-on: ubuntu-latest
  if: github.event_name == 'pull_request'

  steps:
    - name: Checkout PR branch
      uses: actions/checkout@v4
      with:
        ref: ${{ github.event.pull_request.head.ref }}

    - name: Run terraform-docs check
      uses: terraform-docs/gh-actions@v1
      with:
        working-dir: >-
          modules/create-ec2,
          modules/create-key-pair,
          modules/create-tgw,
          modules/create-tgw-vpc-attachment,
          modules/create-vpc,
          modules/security
        output-file: README.md
        output-method: inject
        fail-on-diff: true
```

`fail-on-diff: true` causes the job to exit non-zero if the rendered output differs from the committed `README.md`, preventing a PR from merging with stale docs.

The official action `terraform-docs/gh-actions@v1` installs the CLI and handles the diff check — no separate install step needed.

### Step 4 — Add `docs/tools/terraform-docs.md`

Create a short reference document at `docs/tools/terraform-docs.md` (following the same pattern as `infracost.md` and `prek.md`) explaining:

- What terraform-docs does
- How the pre-commit hook works locally
- How the CI job enforces freshness on PRs
- How to run it manually

### Step 5 — Update `specs/index.md`

Mark feature 12 as Complete once all steps are merged.

## Key Decisions

- **Scope: modules only** — `envs/` directories are root modules consumed directly by operators, not by other Terraform code. Documentation value is low and the signal-to-noise ratio would be poor. Only `modules/` gets generated READMEs.
- **`inject` output method** — allows the `README.md` to contain hand-written content above/below the generated block. This is safer than `replace`, which would overwrite the entire file.
- **`fail-on-diff: true` in CI** — the hook alone is not sufficient enforcement. Developers can bypass prek with `--no-verify`. The CI check ensures docs are never stale on `main`.
- **Reuse existing `antonbabenko/pre-commit-terraform` rev** — avoids pinning a separate repo for the local hook. `terraform_docs` is already a supported hook id in v1.105.0.
- **`terraform-docs/gh-actions@v1` in CI** — the official action; no need to install the binary separately or maintain a version pin in workflow YAML.
- **No `.terraform-docs.yml` config file** — the hook args and action inputs are sufficient for this repo's structure. A config file would be added only if customisation (e.g. sorting, sections) becomes necessary later.
